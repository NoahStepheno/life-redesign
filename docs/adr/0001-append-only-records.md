# 用户的计划与记录只追加、不覆盖

Vision、Anti-vision、Year Goal、Month Project、Constraints 以及每日 Verdict 全部采用追加式存储:每次修改写入一个带日期的新版本,旧版本永不改写,当前版本取最后一条。原因是复盘的核心价值是用旧版本核对用户的言行("三个月前你写的是 X,现在改成 Y,是想清楚了还是在逃避?"),覆盖会让用户能悄悄降低标准而不留痕迹。

## Considered Options

- **直接覆盖**:文件最小、实现最简单,但丢失演进轨迹,复盘失去依据。
- **覆盖加 git 历史**:依赖用户自己启用 git,且 AI 读取历史版本成本高、不可靠。

## Consequences

- 文件会随时间变长,但数据量很小,可接受。
- skill 不提供删除能力;归档由用户手动改目录名完成。
- 澄清边界:CLI 自身永不删除、也不改写任何内容。唯一会改动文件名的情形,是一日协议(One-day Protocol)的片段在两种已定义的场合被**标记**(重命名为 `.archived.md` / `.discarded.md`,内容原样保留):协议超过 7 天未完成而搁置,或隔夜后用户确认感觉已淡去(`confirm-feeling faded`)。整个数据目录的归档仍由用户手动完成。
