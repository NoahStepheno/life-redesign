# Life Redesign 方案

基于 Dan Koe《How to fix your entire life in 1 day》([原文](./how-to-fix-your-entire-life-in-1-day.md))的人生重建引导系统。术语定义见根目录 `GLOSSARY.md`,存储决策见 [ADR-0001](./adr/0001-append-only-records.md)。

## 1. 目标与原则

用户安装后,先用一次性的"一天协议"挖掘自己、产出 Anti-vision / Vision / 年目标 / 月项目 / 底线;之后每天被轻量推送、每晚打卡,系统持续察觉是否走偏,并按月、年复盘。

行为准则(写入 `PROTOCOL.md`):

1. **AI 只做提问者、镜子和记录员**,不替用户写答案、不代写愿景。用户答得敷衍就追问。
2. **评判必须严格,不迎合**。判定必须附理由;用户反驳不会改判,除非给出新的事实。
3. **只追加、不覆盖、skill 不提供删除。**
4. **遇到自伤、严重抑郁等危机迹象,停止按协议逼问**,建议寻求专业帮助。本工具是自我反思工具,不是心理治疗。
5. 交互语言默认中文,跟随用户语言;原文问题翻译为自然中文,保留英文原文作参考。

## 2. 三层架构(客户端无关)

| 层 | 内容 | 说明 |
|---|---|---|
| 核心层 | 本地数据目录 + 中立的 `PROTOCOL.md` + 推送/读写脚本 | 协议与规则只写一份 |
| A 档适配 | Claude Code 的 `SKILL.md`;其他 harness(Codex CLI、Gemini CLI、Cursor、opencode 等)的 `AGENTS.md` | 都引用同一份 `PROTOCOL.md`,完整能力:自动读写、追问、复盘 |
| B 档适配 | 纯聊天 App(ChatGPT、豆包、DeepSeek)的"系统提示词包" | 开聊前粘贴状态快照;结束时 AI 输出"更新块",用户手动贴回本地文件。推送正常,但回答与 AI 复盘需手动 |

第一版交付:核心层 + Claude Code + 通用 `AGENTS.md` + B 档提示词包与快照/更新块格式(不做自动化)。推送第一版只支持 macOS(launchd),Linux 后置。

## 3. 入口

一个 skill、多个入口,共享同一份数据目录和 `PROTOCOL.md`,例如 `/life-redesign checkin`。

| 入口 | 场景 | 触发 |
|---|---|---|
| `start` | **一次性**的一天协议;之后仅在用户明确要求或年复盘时重做 | 用户 |
| `checkin` | 每晚打卡,产出判定 | 推送或用户 |
| `review` | 月复盘、年复盘,用旧版本核对言行 | 推送或用户 |
| `plan` | 修改 Vision、目标、底线,追加新版本 | 用户 |
| `notify` | 安装、卸载、调整推送与勿扰日 | 用户 |

## 4. 数据目录

位置 `~/.life-redesign/`,纯文本,人类可读、可手改、可 git 备份,完全本地。

```
~/.life-redesign/
├── state.json          # 协议进度、推送配置、连续偏离/未记录计数(只放机器状态)
├── anti-vision.md      # 追加式,每个版本带日期
├── vision.md           # 追加式
├── goals.md            # 年目标、月项目、底线,追加式
├── protocol/
│   └── 2026-01-15.md   # 每次一天协议的完整答案
└── log/
    └── 2026-01-15.md   # 每日:杠杆完成情况、判定、理由
```

追加式文件用日期标题分段,当前版本取最后一段。

## 5. 一天协议(`start`)

早上挖掘 → 白天打断 → 晚上综合,问题取自原文第 VI 节,按"逐题落盘"推进。

**中断恢复:**

1. 每答完一题落盘,`state.json` 记录进度。
2. 当天内中断:下次从断点继续。
3. 隔天才回来:早晨答案保留,但先问"那天的感受还在吗?";若已淡去,这一段作废重做(原文前提是张力最强时一口气走完)。
4. 超过 7 天未完成:标记"搁置",下次重新开始,旧答案归档。
5. 协议完成前**不启动日常推送**。

**协议当天**:按原文推送全部 6 条打断问题 + 3 条备选问题。

**重做**:产生新版本的 Anti-vision / Vision,旧版本保留,AI 在新旧之间做对比追问。整体归档由用户手动把数据目录改名为 `archive-日期` 后重新开始。

## 6. 每日察觉(`checkin`)

每晚逐项审问三类 Drift:

1. **行动偏离**:今天的 Daily Levers 做了没有,必须说出具体做了什么,"差不多""在想"不算。
2. **身份保护**:有没有哪件事是为了维护旧身份、而非真实欲望。
3. **靠近反愿景**:今天更接近 Anti-vision 的周二,还是 Vision 的周二。

判定三档:**在轨 / 轻微偏离 / 走偏**,附理由。判定只在交互式 `checkin` 中产生。

**升级与漏打卡:**

- 漏打卡记为 **未记录**,不自动算走偏。
- 连续 3 天走偏,或连续 3 天未记录,触发加重追问。
- 沉默期推送降频,只保留晚间一条。
- 用户回来后,先问"这几天发生了什么",再恢复流程。
- 未记录天数进入月复盘数据。
- 勿扰日不计入未记录,也不触发升级。

## 7. 复盘(`review`)

- **月复盘**:读取当月全部 `log/`,统计判定分布与未记录天数;用 `goals.md` 的旧版本核对言行;检视 Month Project 是否支撑 Year Goal;决定下月项目。
- **年复盘**:对比 Year Goal 与现实;询问是否重做一天协议;重做后与旧版本对比追问("你一年前最怕的是 X,现在是 Y,发生了什么?")。

## 8. 主动推送

由安装脚本在系统层注册(macOS launchd),弹系统通知,内容来自本地文件,不依赖任何模型客户端。

**日常每天最多 3 条(默认,可在 `notify` 修改):**

| 时间 | 内容 |
|---|---|
| 08:30 | 今天的 Daily Levers + Year Goal 一句话 |
| 11:00–17:00 随机一条 | 从 6 个打断问题中随机抽一个,每天时间不同 |
| 21:30 | 打卡提醒 |

**AI 参与的推送**(例如"你已连续 2 天轻微偏离"):

- 配置"推送用客户端",默认 `claude -p`,可换成 Codex CLI、Gemini CLI 等能无头运行的 harness。
- 无头调用**只读不写**:只能读当天及近 7 天日志,不得修改任何文件,不产生判定。
- B 档用户没有无头能力,退化为固定模板文案。

**隐私:**

- 数据只存本地;安装时明确告知一次:对话内容与无头推送会发送给所选模型服务商。
- **通知中只出现预写的问题,绝不出现用户的私人内容**,避免锁屏泄露。

## 9. 交付物清单

仓库根目录属于开发这个项目的人(开发配置、术语表、ADR、设计文档);用户安装的内容全部在自包含的 `skill/` 下。

```
life-redesign/
├── CLAUDE.md             # 开发配置(Agent skills 块),不随产品分发
├── GLOSSARY.md           # 项目领域词汇,不随产品分发
├── docs/                 # 设计、ADR、原文、docs/agents/
└── skill/                # 用户安装的内容
    ├── SKILL.md          # Claude Code 入口
    ├── AGENTS.md         # 其他 harness 入口
    ├── PROTOCOL.md       # 中立协议:问题、规则、判定准则、行为准则
    ├── prompts/          # B 档(纯聊天 App):system-prompt.md(开聊粘贴的系统提示词包)+ README.md(快照/更新块的用户端说明)
    └── scripts/          # 数据读写、launchd 安装/卸载、通知
```
